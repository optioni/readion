## Why

A mock exam is the highest-signal moment in Readion — a timed, exam-faithful dress rehearsal scored against the real pass mark. The backend for it is fully implemented and archived (`mock-exam`, plus the shared `session-summary`, `weak-areas`, `readiness`, `grounding-verification` it leans on), and the committed Orval client already exposes every endpoint the UI needs. The entry points are wired too: `web-dashboard`/`web-cert-detail` already create an attempt (`useQuickStartActions.startMockExam`) and `router.push('/mock-exams/:id')`, and `ExamHistoryTab` links submitted attempts to the same route for review. What is missing is the destination: the `/mock-exams/[id]` page does not exist. This change builds that full-screen timed-exam experience.

## What Changes

- **Full-screen mock-exam page at `/mock-exams/[id]`** — a minimal-chrome, agent-free, sidebar-free immersive surface that branches on the attempt's `generation` (`preparing` | `ready`) and `status` (`in_progress` | `submitted` | `expired`):
  - **Preparing / stream-in generation** — while `generation === 'preparing'` (server-side: `startedAt` not yet set), show a "Preparing your exam" scene and **poll `GET /api/v1/mock-exams/:id`**, watching `questions[]` grow into the right-hand **question-nav sidebar** as each verified question streams in and a "N / total ready" progress indicator. The wall-clock timer stays paused (the contract returns `deadline`/`remainingSeconds` as `null` until the full verified set is ready); when `generation` flips to `ready`, transition to the active exam.
  - **Active timed exam** — one question at a time with a domain tag, options, Previous / Skip / Next, and a right-hand **question-nav sidebar** (answered / current / unanswered squares + Submit). A **wall-clock countdown** is seeded from the contract's `remainingSeconds` and `deadline` (server-authoritative) and ticks down locally. Answering a question calls `PUT /api/v1/mock-exams/:id/answers/:questionIndex` (zero-based index, per the contract — not the question id). Status colours are hidden during the active exam (exam-faithful).
  - **Resume** — re-entering an `in_progress` attempt rehydrates answers from `questions[].userAnswer`, positions at the first unanswered question, and resumes the countdown from the server's `remainingSeconds` (elapsed time kept counting while away).
  - **Submit & auto-submit on expiry** — a **Submit exam** action calls `POST /api/v1/mock-exams/:id/submit`. When the countdown reaches zero the page auto-submits; if the cleanup cron has already expired the attempt (409 / terminal on refetch), the page refetches `GET /api/v1/mock-exams/:id` and shows the terminal result. Unanswered questions score as incorrect server-side.
  - **Results / score breakdown** — on a terminal attempt render the exam-faithful hero from `MockExamResponse` (overall `score`, `passed` → PASS / FAIL) and the per-domain `domainBreakdown` (`correct` / `total` / `accuracy` with status colours), **plus** the reusable study summary (readiness change, weak-area movement, strongest/weakest, suggested focus, and **Drill my misses**) from `GET /api/v1/mock-exams/:id/summary` rendered through the `SessionSummaryBody` component built by `web-session-view`.
  - **Review mode** — from results, step through every question with the chosen answer, the correct answer revealed, per-option correct/incorrect/dim colours, the explanation, and citation chips. The reveal fields (`correctAnswer`, `explanation`, `citations`) are only present on a terminal attempt, so review is reachable only after submission.
  - **Expired state** — an `expired` attempt renders the same results/review surface framed as auto-submitted-on-expiry rather than a manual submission.
- **Reuse, not rebuild** — the `SessionSummaryBody` component, status-colour helpers (`statusColorForScore` / `statusTextColorClass`), citation chips, Markdown rendering, query-key factory pattern, the minimal-chrome layout, and the timer/progress patterns from `web-session-view`/`web-foundation`. The session **elapsed** timer counts up; the mock exam needs a **countdown to `deadline`** in `HH:MM:SS`, so a sibling countdown composable is added alongside `useElapsedTimer` rather than overloading it.
- **No `yarn codegen`** — every consumed endpoint already exists in the committed `apps/web/src/api/` client (`enrollmentMockExamControllerCreate`/`List`, `mockExamControllerFindOne`/`Submit`/`SaveAnswer`, `mockExamSummaryControllerSummary`/`Drill`).

### New Capabilities
- `web-mock-exam`: The `apps/web` mock-exam page — the full-screen, agent-free timed-exam experience at `/mock-exams/:id`, covering stream-in generation (preparing → ready with the nav sidebar filling), the active timed exam with a wall-clock countdown and per-index answer persistence, resume from the server clock, submit and auto-submit-on-expiry, the post-submission score breakdown by domain (reusing the `web-session-view` summary body), review mode, and the expired state.

## Impact

- **New code**: `apps/web` — the `/mock-exams/[id]` page, an exam header (cert chip, mode label, countdown, flag), a question-nav-sidebar component (preparing / active / review states), an exam question card + options (reusing the quiz-option visual states), a results/score-breakdown component, a review-mode pane, a `HH:MM:SS` deadline-countdown composable, a mock-exam query-key factory, and thin bindings over the committed Orval composables. Playwright e2e spec in `apps/web/e2e/` and co-located component/composable unit specs.
- **Consumed API contracts (already committed in `apps/web/src/api/`)**: `mockExamControllerFindOne` (load / poll / resume), `mockExamControllerSaveAnswer` (answer by zero-based index), `mockExamControllerSubmit` (submit / auto-submit), `mockExamSummaryControllerSummary` + `mockExamSummaryControllerDrill` (post-exam summary + drill). `enrollmentMockExamControllerCreate` is already invoked upstream by `web-dashboard`/`web-cert-detail`; this change consumes the attempt it creates.
- **Reused frontend assets (from `web-session-view`/`web-foundation`, archived)**: `SessionSummaryBody.vue`, `statusColor.ts`, `CitationChip.vue`, `DeltaBadge.vue`, the minimal-chrome layout, the vue-query plugin, and the Orval client.
- **No backend changes, no new entities, no migrations, no codegen.** The mock-exam auto-submit/expiry cron and scoring are owned by the archived backend `mock-exam` change; this change only observes their results. Design reconciliation flags where the `MockExam.html` artboards assume richer payloads than the contracts provide (per-domain weight + passing-threshold markers, a persisted "flag" feature, a numeric passing-score line, an in-exam "Ask agent" affordance) — resolved in `design.md` (behavioural spec + real contract win; artboard extras are derived, made client-only, or dropped) and surfaced as possible follow-up backend changes rather than silently assumed.
- **Dependencies** (all archived): `web-foundation`, `mock-exam`. Reuses `web-session-view`'s `SessionSummaryBody` (also archived).
- **Design**: `../../design/MockExam.html` (shared mirror; referenced in place, not copied).
