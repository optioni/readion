## Why

A study tool that teaches wrong answers is worse than none. SPEC (Grounding & Verification) makes faithfulness to source material a hard guarantee: every generated question/explanation must quote its supporting span verbatim, pass an *independent* verifier before it is ever shown or cached, carry real provenance, and be instantly quarantinable on report. `llm-foundation` shipped the gateway (with the `answer-verification` task type) and a verified-only cache *gate*, but the meaning of "verified", the verifier pass itself, the extractive contract, the regenerate/substitute policy, the provenance shape, and the quarantine path do not exist yet. Standing these up once — before `quiz`, `mock-exam`, and `agent`, all of which depend on them — means each downstream generator plugs into a single grounding contract instead of re-deriving faithfulness guarantees per feature.

## What Changes

- **Extractive-generation contract (shared types + validator).** A structured output shape for any grounded generated item — `question`, `options`, `correctAnswer`, `supportingSpans[]`, `sourceChunkIds[]` — published in `packages/shared`, plus a validator that enforces the contract: every `supportingSpan` must be a verbatim substring of one of the cited `sourceChunkIds`, and the correct answer must be backed by at least one span. An item that cannot be grounded in a quote is rejected before it ever reaches the verifier.
- **Independent verifier pass.** A `VerifierService` that issues a *separate* `answer-verification` utility-model call (distinct from generation, so the model never grades its own work) checking that the correct answer is entailed by the cited span and that every distractor is actually incorrect per the source. Returns a structured verdict — pass/fail, score, per-distractor findings — that becomes the `verified` marker the `llm-cache` gate already requires.
- **Generate → verify → retry → substitute orchestration.** A reusable `GroundedGenerationService` that downstream generators (`quiz`, `mock-exam`) drive by supplying a generation function and retrieval results: it runs the extractive validator, then the verifier; on rejection it regenerates up to a configured N times; if still failing it discards and signals "substitute from a different concept/chunk"; if the topic's retrieval scores are genuinely thin it raises a `fetchMoreMaterial` signal. Users never see an unverified item.
- **Provenance & verdict persistence shape.** A `Provenance` value object (`sourceChunkIds`, `supportingSpans`, verifier verdict + score) defined as a shared embeddable type that the entity-owning changes (`SessionItem` in `sessions`, the question array in `mock-exam`, `QuizResponse` in `quiz`) embed when they persist. Citation chips and the `explainAnswer` tool derive from this stored provenance — citations are real references, not the model re-stating a source. **No entity or table is owned here.**
- **Quarantine + cache eviction path.** A `QuarantineService` that, given a generated item's cache key and its provenance, evicts the cached entry (via the `llm-cache` `evict` API) and produces an immutable quarantine record (item ref + provenance + reason) for admin surfacing — so a reported or auto-flagged item is never reused or served from cache. The user-facing "report this question" HTTP action is wired by `quiz`/`mock-exam`; this change owns the quarantine *mechanism* and the report-intake service it calls.
- **Reading-block & agent grounding contract (no verifier gate).** A documented, testable grounding contract for the non-verifier-gated paths: reading blocks are composed only from cited chunks (extractive grounding + citation chips, with a configurable verbatim cap), and the agent path is governed by an abstention rule ("answer only from retrieved context; abstain rather than guess; abstention may trigger `fetchMoreMaterial`"). This change defines the contract and the verbatim-cap/abstention helpers; the agent system prompt and reading-block composer are assembled by `agent`/`sessions`.
- **Feature-emitted metrics.** Emit (through the `observability` infrastructure) the SPEC grounding metrics: verifier pass/fail rate, regeneration count per item, substitution/abstention rate, and user-reported/quarantined-item rate per certification.

No new entity, no migration, and no new HTTP endpoint are introduced — per the roadmap entity-ownership table `grounding-verification` owns no entity. This is an internal service + contract layer consumed by `quiz`, `mock-exam`, and `agent`.

## Impact

- **Code**: `apps/api/src/grounding/` — `grounding.module.ts`, `verifier.service.ts` (independent `answer-verification` call + verdict), `grounded-generation.service.ts` (validate→verify→retry→substitute→`fetchMoreMaterial`), `extractive-contract.ts` (verbatim-span validator, pure), `quarantine.service.ts` (evict cache + build quarantine record + report intake), `verbatim-cap.ts` / `abstention.ts` (reading-block/agent grounding helpers), grounding metrics emission. Shared contract + provenance types under `packages/shared/src` (extractive item shape, `Provenance` embeddable, verifier verdict, grounding signals).
- **Dependencies (apps/api)**: consumes `llm-foundation` — the gateway's `answer-verification` task type and the `llm-cache` verified-only `set` + `evict` API; and `content-pipeline` — the `semantic-search` retrieval service (provenance-bearing chunks + the similarity threshold used to detect thin coverage). Emits metrics/traces through the existing `observability` infrastructure. No new third-party dependency.
- **Database**: none — no entity, no migration. Provenance is a shared embeddable persisted by the entity owners (`sessions`, `mock-exam`, `quiz`).
- **Entities owned**: none (per the roadmap entity-ownership table).
- **Cross-cutting**: no worker cron attributed to this change. Feature-emitted metrics owned here: verifier pass/fail rate, regeneration count per item, substitution/abstention rate, and user-reported/quarantined-item rate per certification (emitted through the `observability` infrastructure stood up earlier).
- **Out of scope (owned elsewhere)**: actual quiz/explanation/reading-block prompt content and the user-facing "report" endpoint (`quiz`, `mock-exam`); persisting provenance on `SessionItem`/`MockExam`/`QuizResponse` (their entity-owning changes embed the shared type); the agent system prompt and `fetchMoreMaterial` tool implementation (`agent`); the `AuditLog` write on quarantine (`admin` owns `AuditLog`; consumers wire the entry); admin quarantine-review UI (`web-admin`).
- **Depends on**: `llm-foundation` (archived) and `content-pipeline` (archived).
- **Unblocks**: `quiz`, `mock-exam`, `agent`.
